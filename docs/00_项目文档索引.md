# 信息系统项目管理师 RAG 知识库文档索引

## 文档目的

本目录是项目的正式文档入口。项目后续新增功能时，先阅读相关文档，再按照“需求 -> 设计 -> 实现 -> 验收 -> 变更记录”的顺序推进。

## 文档维护原则

1. 文档和代码不一致时，以代码实际行为为准，同时立即补正文档。
2. 设计文档写“为什么这样做”，实现文档写“现在怎么做”。
3. 任何功能没有验收标准，就不视为完成。
4. 影响架构、数据、成本、回答可靠性的改动，必须在变更记录中留下原因。
