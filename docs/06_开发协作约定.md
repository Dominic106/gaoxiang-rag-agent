# 开发协作约定

## 1. 开发前

任何新功能开始前，先明确：

- 为什么做，解决什么学习或检索问题。
- 功能放在哪个阶段，是否超出当前基本盘。
- 会影响哪些模块、数据文件、API 调用和成本。
- 采用什么方案，为什么不采用其他明显方案。
- 如何验证完成，失败时如何处理。

## 2. 开发中

- 优先沿用现有模块和数据格式，避免无必要的重构。
- 代码、配置、索引和文档保持同一套命名。
- 不在日志、文档或回答中泄露 API Key。
- 涉及回答可靠性的改动，必须同时测试“可回答”和“应拒答”两类问题。
- 涉及流程变化时，更新对应 Mermaid 流程图，并保留旧版本。

## 3. 开发后

交付前检查：

- 代码语法和主要路径是否通过。
- 需求验收标准是否满足。
- README、技术说明、任务状态是否需要更新。
- 变更原因、已知限制和下一步是否记录。

## 4. 记忆和决策

重要决策不只依赖聊天上下文，必须写入项目文档。聊天适合讨论，文档负责沉淀；代码负责执行，测试负责证明。
