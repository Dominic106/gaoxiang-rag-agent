# 核心代码质量与回归测试

## 1. 目标

在错题本、复习卡和 Web UI 之前，先确认 RAG 核心链路具备稳定的逻辑、清晰的代码边界、可接受的查询性能和可重复的回归测试。

## 2. 评分维度

| 维度 | 关注内容 | 目标 |
| --- | --- | --- |
| 逻辑正确性 | 问题理解、检索、自救、证据门禁、引用和拒答 | 核心路径无明显逻辑错误 |
| 代码整洁度 | 模块职责、重复初始化、命名、异常处理、可读性 | 核心模块职责清楚，重复逻辑受控 |
| 性能与成本 | BM25/Chroma/模型对象复用、缓存命中、API 调用次数、上下文长度 | 同一进程内重复问题不重复初始化或调用 |
| 功能回归 | 可回答、应拒答、追问、多问题、章节过滤、引用拦截 | 关键行为有自动化验证 |

总分采用 10 分制，但必须同时记录证据，不用单一分数掩盖具体短板。

## 4. 性能基线

重点观察以下行为：

- 同一进程内 BM25 检索器是否重复从磁盘加载。
- 同一进程内 Chroma 和 embedding 对象是否重复创建。
- 同一进程内 DeepSeek 客户端是否重复创建。
- 同一个 query 是否命中 embedding 缓存。
- 多问题输入是否按子问题独立调用，且没有额外的无意义调用。
- 网络请求是否有明确超时，重试次数是否有限。
- 超时、鉴权、响应格式和文件写入异常是否都有稳定事件名和堆栈日志。

## 5. 核心优化边界

本阶段只优化核心 RAG，不实施：

- 回退后自动重算会话、问题历史和学习画像。
- 错题本和复习卡片。
- Web UI。
- 专业 reranker。

这些功能等核心稳定后再进入设计。
